# Repeat Prevention（繰り返し防止）

多くのシナリオでは、Probability Listからのアイテム選択が連続して繰り返されることを防いだり、減らしたりしたいことがあります。
RNGNeedsは繰り返し防止を柔軟かつ強力な方法で処理し、特定のニーズに合わせた動作をカスタマイズできます。 {{ className: 'lead' }}

---

## 概要

繰り返し防止は、同じランダムイベントが連続して発生しないようにしたり、プレイヤーが同じアイテムを繰り返し受け取らないようにするなど、さまざまなゲームメカニクスで重要です。
RNGNeedsは繰り返し防止を処理する3つの方法を提供しており、それぞれ速度、バイアス、繰り返し防止の程度についてトレードオフがあります。

<Note>
    **バイアスについて**

    バイアスとは、設計された（意図された）確率と実際の結果として生じる確率の差を指します。繰り返し防止の方法は、自然な確率分布の選択プロセスから生じた状況を修正しようとするため、バイアスを生じさせる場合があります。そのため、使用する方法、リスト内のアイテム数、実際の分布によって、結果として生じる確率がわずかにずれる可能性があります。

    分布の大部分を占めるアイテムがある場合、そのアイテムは自然と頻繁に選択されます。
    これは、そのアイテムが2回連続で選択される可能性も高くなることを意味します。
    そのため、アイテムが再選択される頻度が高くなり、認識される確率が設計より低く、他のアイテムの確率が高く感じられる場合があります。
</Note>

<Note>
    **速度は重要ですか？**

    ***端的に言えば：*** ほとんどの場合、重要ではありません。

    速度とは、ピック数、選択した選択メソッド、リストのサイズ、繰り返し防止メソッドなどに基づいて、リストから値を選択するのにかかる時間を指します。
    ゲーム開発のほとんどのケースでは、一度に選択する値は1つ、2つ、またはほんのわずかです。例えば、2D10のサイコロロールは2つの選択値です。宝箱を開けるのは最大20個の選択値かもしれません。
    このような状況では、速度は問題になりません。

    ただし、初期化中にアイテムを事前選択し、ゲームプレイ中に<a href={PickHistoryPage.Link}>{PickHistoryPage.Title}</a>機能を使って事前選択済みの値を取得するような場合など、一度に数百万のアイテムを選択する必要がある場合もあります。

    一億個のアイテムを一度に選択するのに約1秒かかる場合があり、5回のイテレーションでShuffle Repeat Preventionを使用すると約2秒かかることがあります。初期化中に事前選択する場合は、これも問題にはなりません。
    速度は、ゲームプレイ中に大量のアイテムを頻繁に一度に選択する必要がある場合に考慮すべき点です。

    RNGNeedsはBURSTコンパイル版の選択メソッドを提供しており、必要な時間を大幅に短縮できる場合があります。結果と速度のテスト方法については、ドキュメントの<a href={TestingOutcomesPage.Link}>{TestingOutcomesPage.Title}</a>ページをご覧ください。
</Note>

## 繰り返し防止のメソッド

- **Spread**：すべての繰り返しを排除し、最も近い有効なアイテムに置き換えます。このメソッドは高速ですが、特に小さなリストや少ないロール数では顕著なバイアスが生じる場合があります。

- **Repick**：選択を再ロールすることですべての繰り返しを排除します。このメソッドは中程度の速度と低いバイアスを提供しますが、確率の低いアイテムをわずかに優遇し、確率の高いアイテムにペナルティを与える可能性があります。

- **Shuffle**：確率を維持しながら繰り返しを大幅に減少させます。このメソッドは大きなリストでは遅くなる可能性がありますが、バイアスはほとんど生じないか、まったく生じません。選択されたアイテムの順序はランダム化されます。

## 繰り返し防止はどのように機能しますか？

**Spread**と**Repick**メソッドは、*実際の選択プロセス中*に機能します。アイテムがランダムに連続して2回選択されるたびに、新しい選択は最も近い有効なアイテムに*spread*されるか、繰り返しでないアイテムが選択されるまで*re-pick*されます。このプロセスは一度に複数のアイテムを選択する際に機能し、Pick Historyを考慮するため、連続した選択の間でも機能します。

**Shuffle**メソッドは少し異なる動作をします。*選択後*に実行されます。選択結果は、InspectorまたはコードでInspectorまたはコードで設定したイテレーション数に基づいて何度かシャッフルされます。
Shuffleはすべての繰り返しを排除することはできませんが、大幅に減少させることができます。その利点は、確率分布が変化せず、設計された設定を反映するという点です。

<Note>
    **Shuffleに関する注意点**

    - Shuffleは選択後に動作し、Pick Historyを考慮しないため、連続した選択の間の繰り返しを防げない場合があります。
    ある選択で最後に選ばれたアイテムが、次の選択で最初に選ばれるアイテムと同じになる可能性があります。ただし、Shuffleはすべての繰り返しを完全に排除できないため、これは通常は問題になりません。
    - Shuffleは一度に3つ未満のアイテムを選択する場合には効果的ではありません。元の確率分布を維持しながら繰り返しを減らし、1回のピックで複数のアイテムを返すように設計されています。
</Note>

## Repeat Preventionの設定

RNGNeedsの他のほとんどの機能と同様に、Repeat PreventionはProbabilityListごとに個別に設定します。デフォルトでは、防止機能はオフになっています。
リストのInspectorで*PICK*セクションを展開し、Repeat Preventionを有効にできます。Selection Methodを選択するボタン（デフォルトはLinear Search）を見つけてください。
クリックすると、Repeat Preventionメソッドを含むドロップダウンが表示されます。

<ImageX className="w-full h-auto" src={repeatPrevention} alt="Repeat Prevention in Inspector" width="1000"/>

<Note>
    スクリーンショットのようにSelection Methodドロップダウンが表示されない場合は、RNGNeedsの<a href={PreferencesPage.Link}>Preferencesウィンドウ</a>で***Advanced Drawer Options***を有効にしてください。
</Note>

コードでPreventRepeatプロパティを使用して、繰り返しアイテム選択の防止方法を定義することもできます：

```csharp {{ title: 'Setting the Repeat Prevention in code'}}
myProbabilityList.PreventRepeat = PreventRepeatMethod.Spread;
```

**Shuffleイテレーション**
Shuffleメソッドを選択した場合、繰り返し選択を減少させるために使用するシャッフルイテレーション数を指定できます。イテレーション数が多いほど繰り返し防止が強化され、値は常に1から5の間に制限されます。

```csharp {{ title: 'Setting the Shuffle Iterations in code'}}
myProbabilityList.ShuffleIterations = 3;
```

## 使用例

繰り返し防止は、ゲームのさまざまな側面に深み、リアリティ、予測不可能性を加えることができる強力な機能です。
特定の要素が連続して繰り返されないようにすることで、プレイヤーにとってより魅力的で没入感のある体験を作り出せます。
繰り返し防止を適用できるインスピレーションとなる例をいくつか紹介します：

- **ユニットの応答**：キャラクターが同じセリフを連続して繰り返さないようにし、リアリズムと没入感を高めます。
- **ルートドロップ**：同じアイテムが連続してドロップしないようにし、報酬の多様性を確保します。
- **敵のスポーン**：同じ敵タイプが繰り返しスポーンしないようにし、ダイナミックな戦闘を作り出します。
- **ランダムイベントやエンカウンター**：異なるランダムイベントを保証することで新鮮さを維持します。
- **NPCの対話選択肢**：繰り返しの対話を防止し、インタラクションをより自然にします。
- **音楽やアンビエントサウンドの選択**：同じトラックの繰り返しを避けてオーディオを向上させます。
- **パズル生成**：異なるパズルやチャレンジを確保してゲームプレイの多様性を保ちます。
- **カードゲームのカードドロー**：同じカードが連続してドローされないようにして公平性を維持します。
- **天候パターン**：連続して同じ天候条件を避けてリアルな環境を作り出します。
- **ランダム化されたクエストやミッション**：異なるクエストやミッションを確保してゲームプレイを新鮮に保ちます。
- **スキルやアビリティの発動**：同じスキルの連続発動を防止して戦闘の多様性を確保します。
- **ランダム化されたアニメーション**：同じアニメーションの連続再生を避けて流動性を加えます。

繰り返し防止は、ゲームメカニクスに深みと多様性を加えるデザイン上の選択肢です。
さまざまなメソッドとその適用方法を理解することで、プレイヤーにとって魅力的で予測不可能な体験を作り出せます。
さまざまなメソッドを試して、特定のニーズに最適なものを見つけ、RNGNeedsが開く創造的な可能性をお楽しみください。

---

<Note>
    **考慮事項**

    - 繰り返し防止は、最近選択されたアイテムの選択確率を減少させることで、確率分布の結果を変更する場合があります。
    - リスト内に有効なアイテムが1つしかない場合、繰り返し防止の設定は無視されます。
    - **Spread**と**Repick**メソッドは選択間で機能しますが、これはInspectorでの結果テスト時には適用されません。これは、テストがProbability ListのPick Historyに書き込まないためです。
    したがって、単一の値の連続選択をテストしている場合、繰り返し防止がオンになっていてもテストで同じ値が2回連続して生成される場合があります。
    ただし、1回のピックで複数の値を選択する場合は、選択プロセス中に動作するため、これらのメソッドでのテストは正常に機能します。

</Note>
