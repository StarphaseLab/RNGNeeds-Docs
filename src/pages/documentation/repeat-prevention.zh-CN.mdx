# 重复预防

在许多场景中，您可能希望防止或减少从 Probability List 中连续选中相同条目的情况。RNGNeeds 提供了一种灵活而强大的重复预防机制，让您可以根据具体需求定制其行为。{{ className: 'lead' }}

---

## 概述

重复预防在各种游戏机制中至关重要，例如确保同一随机事件不会接连发生，或玩家不会连续获得相同的道具。RNGNeeds 提供了三种重复预防方法，每种方法在速度、偏差和重复预防程度之间各有取舍。

<Note>
    **理解偏差**

    偏差是指设计（预期）概率与实际结果概率之间的差异。重复预防方法可能会引入偏差，因为它们试图纠正自然概率分布选择过程所产生的结果。因此，实际概率可能会略有偏差，具体取决于所用方法、列表中的条目数量及其实际分布情况。

    如果某个条目占据了大部分的概率分布，它自然会被更频繁地选中。这也意味着该条目连续被选中两次的概率更高。因此，该条目将更频繁地被重新抽取，这可能导致其感知概率低于设计值，而其他条目的感知概率则相应偏高。
</Note>

<Note>
    **速度重要吗？**

    ***简短回答：*** 在大多数情况下，不重要。

    速度是指根据抽取次数、所选选择方法、列表大小、重复预防方法等因素，从列表中选择值所需的时间。在游戏开发的大多数情况下，您一次只需选择一个、两个或少量值。例如，投掷 2D10 骰子是抽取两个值，打开一个宝箱可能最多抽取 20 个值。在这些情况下，速度不是问题。

    然而，有时您可能需要一次性选择数百万个条目——例如，在初始化阶段预先选择条目，并使用 <a href={PickHistoryPage.Link}>{PickHistoryPage.Title}</a> 功能在游戏过程中检索预选值。

    一次性选择一亿个条目可能需要一秒钟，使用五次迭代的 Shuffle 重复预防方法可能会使时间增加到两秒。如果您是在初始化阶段进行预选，这应该仍然不是问题。速度只是在您需要在游戏进行中频繁一次性选择大量条目时需要考虑的因素。

    RNGNeeds 提供了 BURST 编译版本的选择方法，可以显著减少所需时间。请访问文档中的 <a href={TestingOutcomesPage.Link}>{TestingOutcomesPage.Title}</a> 页面，了解如何测试您的配置的结果和速度。
</Note>

## 重复预防方法

- **Spread（扩散）：** 消除所有重复，用最近的已启用条目替换重复项。此方法速度较快，但可能会引入明显的偏差，尤其是在列表较小或抽取次数较少时。

- **Repick（重抽）：** 通过重新滚动选择来消除所有重复。此方法速度适中，偏差较低，但可能略微偏向低概率条目，并对高概率条目产生不利影响。

- **Shuffle（洗牌）：** 在保持概率分布的同时大幅减少重复。此方法对于大型列表可能较慢，但引入的偏差极小甚至为零。抽取条目的顺序将被随机化。

---

## 重复预防是如何工作的？

**Spread** 和 **Repick** 方法在*实际选择过程中*运作。每当一个条目被随机连续选中两次时，新的选择要么被*扩散*到最近的已启用条目，要么被*重新抽取*直到选出一个不重复的条目。此过程在一次性选择多个条目时有效，并且由于它会将 Pick History 纳入考量，因此在连续多次选择之间同样有效。

**Shuffle** 方法的工作方式略有不同，它在*选择完成之后*执行。选择结果会根据您在 Inspector 或代码中设置的迭代次数进行多次洗牌。Shuffle 无法消除所有重复，但可以大幅减少重复。其优点在于概率分布不会改变，将如实反映设计设置。

<Note>
    **关于 Shuffle 的说明**

    - 由于 Shuffle 在选择完成后运行且不考虑 Pick History，它可能无法防止连续选择之间的重复。上一次选择中最后抽取的条目可能与下一次选择中第一个抽取的条目相同。不过，由于 Shuffle 本身也无法完全消除所有重复，这通常不是问题。
    - 当一次性选择少于 3 个条目时，Shuffle 效果不佳。它的设计目的是在单次抽取中返回多个条目，在尊重原始概率分布的同时减少重复。
</Note>

## 设置重复预防

与 RNGNeeds 的大多数其他功能一样，重复预防针对每个 ProbabilityList 单独设置。默认情况下，预防功能是关闭的。您可以在列表的 Inspector 中展开 *PICK* 部分来启用重复预防。找到用于选择 Selection Method 的按钮（默认为 Linear Search），点击后将显示包含重复预防方法的下拉菜单。

<ImageX className="w-full h-auto" src={repeatPrevention} alt="Repeat Prevention in Inspector" width="1000"/>

<Note>
    如果您没有看到截图中所示的 Selection Method 下拉菜单，请在 RNGNeeds <a href={PreferencesPage.Link}>Preferences 窗口</a>中启用 ***Advanced Drawer Options***。
</Note>

您也可以通过 PreventRepeat 属性在代码中定义防止重复条目选择的方法：

```csharp {{ title: 'Setting the Repeat Prevention in code'}}
myProbabilityList.PreventRepeat = PreventRepeatMethod.Spread;
```

**Shuffle 迭代次数**

如果您选择 Shuffle 方法，可以指定用于减少重复选择的洗牌迭代次数。迭代次数越多，重复预防效果越好，该值始终被限制在 1 到 5 之间。

```csharp {{ title: 'Setting the Shuffle Iterations in code'}}
myProbabilityList.ShuffleIterations = 3;
```

## 应用示例

重复预防是一项强大的功能，可以为游戏的各个方面增添深度、真实感和不可预测性。通过确保某些元素不会连续重复出现，您可以为玩家创造更具吸引力和沉浸感的体验。以下是一些可以应用重复预防的启发性示例：

- **单位台词：** 确保角色不会连续重复相同的台词，增强真实感和沉浸感。
- **战利品掉落：** 防止同一道具连续掉落，确保奖励的多样性。
- **敌人刷新：** 避免相同类型的敌人连续刷新，创造动态的战斗体验。
- **随机事件或遭遇：** 确保不同的随机事件出现，保持新鲜感。
- **NPC 对话选项：** 通过防止重复对话，使交互感觉更自然。
- **音乐或环境音效选择：** 避免重复播放相同曲目，提升音频体验。
- **谜题生成：** 通过确保出现不同的谜题或挑战，保持玩法多样性。
- **卡牌游戏中的抽牌：** 通过防止连续抽到相同的牌，维持游戏公平性。
- **天气模式：** 通过避免连续出现相同的天气条件，创造真实的环境。
- **随机任务或关卡：** 确保不同的任务或关卡出现，保持游戏新鲜感。
- **技能或能力激活：** 通过防止连续激活相同的技能，确保战斗多样性。
- **随机动画：** 通过避免连续播放相同的动画，增添流畅感。

重复预防可能是一种为游戏机制增添深度和变化的设计选择。通过了解不同的方法及其应用方式，您可以为玩家创造引人入胜、充满不可预测性的体验。尝试不同的方法，找到最适合您具体需求的方案，享受 RNGNeeds 为您开启的创意可能性。

---

<Note>
    **注意事项**

    - 重复预防可能会通过降低最近被选取条目的选中概率来改变概率分布结果。
    - 如果列表中只有一个已启用的条目，重复预防设置将被忽略。
    - 虽然 **Spread** 和 **Repick** 方法可以在多次选择之间发挥作用，但这不适用于在 Inspector 中测试结果时的情况。这是因为测试不会写入 Probability List 的 Pick History。因此，如果您在测试单个值的连续选择时，即使开启了重复预防，测试也可能会连续产生相同的值。但是，当在一次选取中选择多个值时，这些方法在测试中仍然有效，因为它们在选择过程中运作。

</Note>
