RNGNeeds 変更履歴ページへようこそ。ここでは、プラグインに加えられたアップデートと改善の詳細な履歴をご確認いただけます。

## v1.0.0　2025年12月2日リリース

### 新機能

- **[NEW] IEnumerable の実装** - ProbabilityList のインスタンスに対して直接 `foreach` ループを使用できるようになり、リスト内のアイテムの反復処理が容易になりました。
- **[NEW] 複数アイテムを追加するメソッド** - 提供された値から複数のアイテムを ProbabilityList に作成・追加できる新しいメソッドが追加されました。

    - `void AddItems(IEnumerable<T> values, bool enabled = true, bool locked = false)` - 列挙可能なコレクションから複数のアイテムを追加します
    - `void AddItems(bool enabled, bool locked, params T[] values)` - 提供された値から複数のアイテムを追加します

- **新しいカラーパレット - Fireworks & Champagne** - このリリースを 2 つの新しいテーマカラーパレットでお祝いしましょう。Fireworks テーマは鮮やかでダイナミックな色彩をもたらし、Champagne グラデーションはよりエレガントで洗練されたパレットを提供します。

### Inspector の改善

- **[NEW]** Display Option Buttons をコンパクトなドロップダウンにグループ化するオプションが追加され、ドロワーのヘッダーの水平スペースが大幅に最適化されました。狭い Inspector で役立ちます！これは RNGNeeds Preferences にあるグローバル設定です。
- **[NEW]** ドラッグで数値を調整する機能が追加されました。値フィールドの左側に小さな視覚的なヒントが表示され、その値が数値であることを示します。
- **ビジュアルの改善** - フォントサイズと Inspector 要素を最適化し、よりコンパクトな外観にしました。この変更により、ProbabilityList Inspector の全体的な読みやすさが向上しています。
- **ストライプの改善** - Weights Priority モードでパーセンテージと重みの値の順序が逆になり、重要な値が目立つようになりました。さらに、パーセンテージが非表示の場合に値に重みアイコンが追加されました。これらの変更により、重みを使用した作業時のストライプの読みやすさが大幅に向上しました。
- カラーパレットのインポートロジックが改善されました。カスタムパレットをインポートする際に、既存のパレットに追加するか完全に置き換えるかを選択できるようになりました。

### その他の変更と修正

- Unity のバージョンによっては、カスタムオブジェクトの ProbabilityList でクラスのフォールドアウトが正しく表示されない問題を修正しました。
- 警告がデフォルトのログレベルから削除されました。デフォルトでは、ログは Info & Hints に設定されるようになりました。

### 破壊的変更

- `PLCollection.PickFromAll` メソッドが削除されました。このメソッドは廃止予定とマークされており、v0.9.6 で `PLCollection.PickValuesFromAll` に置き換えられていました。

*このリリースで実装された機能提案をしてくださった Discord ユーザーの **Jake Pine** と **Krptck** に感謝します！*

## 0.9.9 (Beta)　2024年11月20日リリース

### 新しい主要機能 - 重み付き分布

デフォルトのパーセンタイルベースのワークフローに加えて、重みを使って確率を設計できるようになりました。重み付き分布は非常に要望の多かった機能であり、当プラグインが解決を目指す一般的な RNG ニーズの一つです。重みを活用することで、確率設計に実績のあるアプローチを適用でき、ゲームデザインの選択肢が大幅に広がります。

### バグ修正

- Inspector の「Reset All Probabilities」ボタンが一部の状況でエラーを大量に出力する問題を修正しました
- アイテムの受信確率影響値が NaN または Infinity の場合に選択が失敗する問題を修正しました

## 0.9.8 (Beta)　2024年9月30日リリース

### Inspector の改善

- **[NEW] リストエントリの非表示** - Inspector でリストエントリを非表示にするオプションが追加されました。非表示のとき、ボタンにリスト内のエントリ数が表示されます。この機能は、リストのセットアップが完了した後に Inspector をシンプルで読みやすく保つのに役立ちます。

- **ヘッダーバーボタンの改善** - ヘッダーバーのすべてのオプションボタンをテキストからアイコンに変更し、よりクリーンで統一されたビジュアルに改善しました。

### バグ修正

- **PLCollection Inspector のビジュアル問題** - Editor Light スキン使用時の PLCollection Inspector のビジュアル問題を修正しました。
- **Probability Lists のマルチ編集問題** - ScriptableObject をマルチ編集する際に Probability Lists のアイテムが無効になる問題を解決しました。

## 0.9.7 (Beta)　2024年6月12日リリース

### 新しい主要機能 - 消耗可能リスト

消耗可能リスト（Depletable Lists）は、アイテムに使用制限を設けることができる強力な機能です。
各アイテムの最大ユニット数と利用可能ユニット数を設定することで、ゲームメカニクスの幅が大きく広がります。
消耗可能アイテムは、ゲーム報酬のユニークな選択の確保や、カードデッキやルートテーブルのような同一アイテムの複数インスタンス管理など、さまざまな方法で活用できます。

### Inspector の改善

- **[NEW]** 選択した機能に対してドキュメントリンク付きの **Option Buttons** が導入されました。これらのボタンを Shift クリックすると、その特定の機能のオンラインドキュメントまたはガイドが開きます。
- **[NEW]** リスト内のすべてのアイテムを一度に変更するための **Action Menu** が導入されました。
- ヘッダーから Stripe セクションボタンが削除されました。Stripe Height のオプションは Theme セクションで利用できるようになりました。
- **TEST** ボタンの改善 - Control クリック（macOS では Command クリック）を使用すると、テスト実行前に消耗可能アイテムのユニットが補充されます。

### サンプルの改善

- **DeckBuilder** が消耗可能アイテムと連携するよう更新されました。
- **CardDeck** のドローメソッドが、カードを削除する代わりにユニットを消耗するよう更新されました。

### バグ修正

- 一部の Unity バージョンでスクロールホイールによる確率調整が反転していた問題を修正しました。
- Welcome Window 内のリンク切れを修正しました。

## 0.9.6 (Beta)　2024年5月13日リリース

### PLCollection の改善

- **[New]** コレクション内の Probability Lists に名前を付ける機能が追加されました。名前は Inspector に表示され、編集できます。リスト名は、リストの取得や値のピックに使用できます。
- **[New]** コレクション内の Probability Lists を並べ替える機能が追加されました。
- **[New]** 個々のリストまたはコレクション全体から値を選択するための便利なメソッドが複数追加されました。

### PLCollection メソッドの更新

追加されたリストの名前を設定する任意パラメーターを持つよう AddList メソッドが変更されました
- `void AddList(string name = "")`
- `void AddList(ProbabilityList<T> list, string name = "")`

RemoveList メソッドにリストが見つかって削除されたかどうかを示す boolean の戻り値が追加されました
- `bool RemoveList(int index)`

GetList メソッドの戻り値の型が `IProbabilityList` インターフェースではなく `ProbabilityList<T>` を直接返すよう変更されました
- `ProbabilityList<T> GetList(int index)`

**破壊的変更**

- 呼び出しをより明示的で情報豊かにするため、`PLCollection.IsListEmpty` メソッドのシグネチャが変更されました。メソッドは、リストが見つかったかどうかと空かどうかを示す 2 つの boolean のタプルを返すようになりました。

    - **旧** `public bool IsListEmpty(int index)`
    - **新** `public (bool ListFound, bool IsEmpty) IsListEmpty(int index)`

- `PLCollection.PickFromAll()` が廃止予定としてマークされました。このメソッドは v1.0 リリースで削除されます。新しい `PickValuesFromAll()` をご使用ください。

## 0.9.5 (Beta)　2024年3月28日リリース

- **[New]** 個々のアイテムで **Influence を反転**させる機能が追加されました。この機能により、受信する Influence の制御が強化され、外部要因に基づいた動的な確率調整に関してゲームデザイナーにより多くの選択肢を提供します。
- **[New]** ProbabilityItem プロパティ：
    - `public bool InvertInfluence` - 受信した確率の Influence を反転させるかどうかを決定します。true に設定すると、このアイテムの確率に対する Influence の効果が逆転します。
- **[New]** ProbabilityList 便利メソッド：
    - `.SetItemInfluenceSpread(int index, Vector2 spread)` - インデックスで識別されるリスト内のアイテムの Influence スプレッドを指定します。このスプレッドは Influence によってアイテムの確率が調整される範囲を定義します。
    - `.SetItemInvertInfluence(int index, bool invertInfluence)` - 特定のアイテムの確率に対する Influence 効果を反転させるかどうかを決定します。反転は、正の Influence がアイテムの確率を下げ、負の Influence が確率を上げることを意味します。

**バグ修正：**

- Influence を受けた確率のグラフ表示が Influence を受けていないアイテムとずれていた問題を解決しました。
- 確率プレビューバーとスプレッドスライダーに関連する複数のアライメント問題に対処しました。

## 0.9.1 (Beta)　2023年8月7日リリース

- **AddItem** メソッドとそのオーバーロードが新しく作成された **ProbabilityItem** を返すようになりました。これにより、アイテムをリストに追加した直後に手動で取得することなく、アイテムのプロパティを変更できます。
- デフォルトのエディターログレベルで警告メッセージも表示されるようになりました。これは Beta 期間中のデフォルト動作であり、後で Info & Hints に戻される予定です。この変更はデフォルト設定にのみ適用されます。現在のログレベルはいつでも環境設定で変更できます。
- シリアライズできないカスタム型を扱う ProbabilityList を Inspector で確認する際に警告メッセージが表示されるようになりました。
- Repeat Prevention メソッドのメソッドサマリーが更新されました。

**破壊的変更**

- **ProbabilityItem** コンストラクターを更新しました - 明確さを高め、アイテム作成をより意図的なものにするため、ProbabilityItem コンストラクターが改善されました。パラメーター **T value** と **float baseProbability** がオプションではなくなり、各アイテムが値と基本確率で明示的に初期化されるようになりました。空のアイテムや 0% 確率のアイテムを作成するオプションを削除することで、ProbabilityList 内の透明性を高め、その動作に関する曖昧さを減らすことを目指しています。この変更により、開発者は確率分布をより明確に理解でき、ProbabilityList 使用時のより予測可能で整理されたアプローチが促進されます。
- メソッド **SetItemProbability** と **AdjustItemProbability** は、それぞれ **SetItemBaseProbability** と **AdjustItemBaseProbability** に名前が変更されました。この変更により、変更されていない「基本」確率と調整後の確率の区別が明確になり、リスト設計時のユーザーにとってより直感的で正確な表現が確保されます。
