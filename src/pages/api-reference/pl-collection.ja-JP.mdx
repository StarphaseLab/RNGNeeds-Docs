# PLCollection&lt;T&gt;

まず実践的なガイドが必要ですか？<a href={GuidePLCollection.Link}>{GuidePLCollection.Title}</a>から始め、このページをコレクションAPIのコンパクトなコードリファレンスとしてご活用ください。 {{ className: 'lead' }}

`PLCollection<T>`は複数の`ProbabilityList<T>`インスタンスをひとつのコレクションにまとめます。

ひとつのリストでは不十分で、名前付きまたはインデックス付きのリストグループをより上位の構造で管理したい場合に使用します。

---

## 代表的なユースケース

- グループ化されたルートテーブル
- 名前付きダイアログプール
- エンカウントカテゴリー
- マルチバイオームのスポーンリスト
- 複数のProbabilityListをひとまとめにする必要があるあらゆるシステム

## 名前 vs インデックス

<Note>
  <p><strong>名前を使った方がAPIとして明確になることが多いです。</strong></p>
  <p>インデックスによるアクセスは厳密に制御された内部システムには適していますが、コレクションがコンテンツグループを表す場合、名前ベースのアクセスの方が通常は読みやすく保守性も高くなります。</p>
</Note>

<Note>
  <p><strong>リスト名は一見して思うよりも重要です。</strong></p>
  <p><code>ListName</code>は表示用のオプションラベルに過ぎないわけではありません。エディターのワークフローや、名前でリストを取得・選択するコードにおいて、<code>PLCollection&lt;T&gt;</code>の名前ベースのルックアップを実用的にするものでもあります。</p>
</Note>

## 使用例

```csharp
var responses = new PLCollection<string>();
responses.AddList("Friendly");
responses.AddList("Hostile");

responses.GetList("Friendly")?.AddItems("Hello", "Good to see you", "Welcome back");
responses.GetList("Hostile")?.AddItems("Go away", "Not interested", "Leave me alone");

responses.PickValueFrom("Friendly", out var line);
```
