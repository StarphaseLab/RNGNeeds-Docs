# Seed Providers

Seed providers control how RNGNeeds generates new seeds.

This matters when you care about:

- deterministic behavior
- reproducible debugging
- automated tests
- custom game-wide randomness policies

## The two layers to understand

### Global seed provider

Configured through <a href={API_RNGNeeds.Link}>{API_RNGNeeds.Title}</a>. This controls how RNGNeeds generates fresh seeds globally whenever a list asks for a new one.

### Per-list seed behavior

Controlled on each `ProbabilityList<T>` through `Seed`, `CurrentSeed`, and `KeepSeed`. This controls whether a list keeps or regenerates its seed between picks.

A custom seed provider only needs to supply new seed values, but that simplicity is exactly what makes it useful: you can plug in your own deterministic or centralized seed strategy without changing selection code elsewhere.

## Default behavior

RNGNeeds ships with a default seed provider used by `RNGNeedsCore` unless you replace it.

## Typical workflows

<MemberGroup title="Common seeding scenarios" tone="amber">
  <Member kind="USE" color="zinc" name="Keep the same seed per list">
    Set <code>KeepSeed = true</code> on the list and assign a seed manually if you want reproducible repeated picks from that list configuration.
  </Member>
  <Member kind="USE" color="zinc" name="Generate fresh seeds automatically">
    Leave <code>KeepSeed = false</code>. The list regenerates its seed before each pick using the current global seed provider.
  </Member>
  <Member kind="USE" color="zinc" name="Replace global seed generation">
    Register your own provider through <code>RNGNeedsCore.SetSeedProvider(...)</code>.
  </Member>
</MemberGroup>

## Example custom provider

```csharp
public class FixedSeedProvider : ISeedProvider
{
    private uint current = 12345;

    public uint NewSeed => current++;
}

RNGNeedsCore.SetSeedProvider(new FixedSeedProvider());
```
