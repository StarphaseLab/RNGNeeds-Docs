# Depletable List の使用例

このページでは、Depletable List を使用して一般的なゲームメカニクスでユニークな結果を実現する実践的な例を紹介します。アイテムの入手可能数を制限することはゲームデザインにおける強力なツールであり、多様で魅力的なゲームプレイ体験を作り出すことができます。 {{ className: 'lead' }}

## リソース収集

多くのゲームでは、資源の採掘ポイントは少数の一般的なリソースを産出するように設定されており、さらにレアなリソースが限られた数だけ手に入る可能性があります。このシナリオは Depletable List を使って効果的にシミュレートでき、各リソースタイプの入手可能数を完全にコントロールできます。

ゲーム世界でよく見られる鉄鉱脈を例に考えてみましょう。これはプレイヤーにとって定番のリソースであり、時折貴重な宝石を報酬として与えることもあります。

<ImageX className="w-full h-auto" src={depListExamplesIronVeinA} alt="Depletable List Examples - Iron Vein A" width="1000"/>

この Iron Vein は、無制限の **Iron Ore** と **Heavy Stone** を頻繁に提供しながら、最大3個の **Gold Nugget** と1個の **Opal** をレアな確率で産出するよう設計されています。2つのメインリソースは非枯渇（non-depletable）に設定されており、常に安定して収集できます。一方、レアな宝石は枯渇（depletable）に設定されており、入手可能数はそれぞれ3個と1個に制限されています。

採掘の試みごとに、プレイヤーは **Pick Count** 設定で決まる1〜3個のアイテムを抽出できます。枯渇アイテムを採掘するとその数量が消費され、ゼロになると入手不可になります。一方、非枯渇アイテムは常に利用可能な状態を維持します。


### 採掘回数による枯渇

リソースの採掘ポイントに制限を設け、枯渇のロジックを導入することは非常に有効です。効果的なアプローチの一つは、採掘ポイントが枯渇するまでの採掘回数を固定値として設定することです。

```csharp {{ title: 'Depleted by Mining Attempts'}}
using System.Collections.Generic;
using RNGNeeds;
using UnityEngine;

public class ResourceDeposit : MonoBehaviour
{
    public ProbabilityList<Resource> resourceDeposit;
    
    public int miningAttempts = 0;
    public int maxMiningAttempts = 5;
    
    public List<Resource> MineDeposit()
    {
        miningAttempts++;
    
        if (miningAttempts >= maxMiningAttempts)
        {
            // Here, we would typically disable the depleted resource deposit
            // For example, disable this GameObject or make it non-interactable
        }
    
        return resourceDeposit.PickValues();
    }
}
```

このコードでは、採掘のたびに `miningAttempts` カウンターをインクリメントします。
`miningAttempts` が `maxMiningAttempts` に達するか超えた時点で、採掘ポイントは枯渇したとみなされ、それ以上の採掘ができなくなります。

### リソースの入手可能状態による枯渇

別のアプローチとして、採掘ポイント内の特定のリソースが枯渇したかどうかを監視する方法があります。次の採掘ポイントの設定を考えてみましょう。

<ImageX className="w-full h-auto" src={depListExamplesIronVeinB} alt="Depletable List Examples - Iron Vein B" width="1000"/>

**Check For Depleted Resource** 変数を追加し、**Iron Ore** アイテムを枯渇可能（depletable）に変更して利用可能数を5に設定しました。以下のロジックは、指定されたリソースが枯渇しているかどうかを確認し、それに応じて採掘ポイントを無効化します。

```csharp {{ title: 'Depleted by Resource Check'}}
public Resource checkForDepletedResource;
public ProbabilityList<Resource> resourceDeposit;

public List<Resource> MineDeposit()
{
    var minedResources = resourceDeposit.PickValues();
    if (resourceDeposit.TryGetProbabilityItem(checkForDepletedResource, out var depositResource))
    {
        if(depositResource.IsDepleted)
        {
            // disable the depleted resource deposit
        }
    }

    return minedResources;
}
```

この採掘ポイントでは、**Iron Ore** が枯渇するまで採掘が可能で、枯渇した時点で採掘ポイントが無効化されます。

このアプローチの優れた点は、ゲームデザイナーがどのリソースが採掘ポイントの枯渇をトリガーするかを完全にコントロールできることです。
各アイテムを枯渇可能に設定してその数量を割り当てることで、それぞれの採掘ポイントをゲーム独自のメカニクスやニーズに合わせてカスタマイズできます。
